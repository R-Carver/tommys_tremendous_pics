Project Decisions

tommys_pics: portfolio website for a starting professional photographer.

This file is the single record of project decisions. Update it whenever a decision is made, changed or reversed. Do not delete old decisions; mark them as superseded.

Constraints

  • A first version must be ready to demonstrate within 1–2 hours of implementation.
  • Hosting is on Cloudflare, free plan. No custom domain is needed at the start.
  • A very simple CMS (content management system) is mandatory. An admin must be able to upload images, set their category and set their order.
  • The CMS security must be very simple and quick to implement.
  • Expected volume: 20–100 images at the start, in 4–6 categories.

Decisions

D-001

Base template: HTML5 UP "Lens"

Accepted2026-10-19
Decision
We use HTML5 UP Lens as the base of the public website.
Why
It is built only for photos. It has a thumbnail strip and a full-screen viewer with smooth crossfades. It is plain static HTML, CSS and JS with no extra complexity.
Alternatives
HTML5 UP Multiverse, HTML5 UP Big Picture, and hosted builders such as Pixpa (look only, no reusable code).
Notes
The license is Creative Commons Attribution. The site must credit HTML5 UP, for example with a footer link. Lens has no categories, so we add a category menu ourselves. Style ideas to borrow later: color fading in on hover (Brother Jones, Pedro Agostinho Cruz).
D-002

Hosting: Cloudflare Pages (free plan)

Accepted2026-10-19
Decision
The site is hosted on Cloudflare Pages under the free *.pages.dev address.
Why
It is free, fast, and can run small server functions next to the static site.
Notes
A custom domain can be added later without changing the code.
D-003

Architecture: static site + Pages Functions + custom mini CMS (Option B)

Accepted2026-10-19
Decision
The public site is static. It loads the image list at runtime from an API. A small admin page and a few Pages Functions handle upload, ordering and deletion. No framework and no build step.
Why
Changes appear immediately without a rebuild. No external accounts are needed. The code is small (about 200–300 lines) and fully under our control.
Alternatives
Option A: images in the Git repository and a Git-based CMS (Decap CMS or Sveltia CMS). Rejected because every change needs a rebuild, the admin needs a GitHub account, and the OAuth login setup is too slow for the time budget.
D-004

Image storage: Cloudflare R2

Accepted2026-10-19
Decision
Images and the manifest are stored in an R2 bucket. Images are served through a Pages Function (/img/<path>).
Why
R2 is real file storage with path-like names. The free tier gives 10 GB of storage and free downloads. 100 photos use about 1% of that.
Fallback
Cloudflare may require a payment method to activate R2. If that is not acceptable, we switch to Workers KV (1 GB, 25 MB per entry, 1,000 writes per day on the free plan). The code changes little.
D-005

Data model: one manifest file, category prefixes

Accepted2026-10-19
Decision
A single manifest.json in R2 is the source of truth for categories, images and order. The order of an array is the display order. Image files use the category as a path prefix.
Why
Changing the order only rewrites one small file. Files never need to be renamed.
Example
landscape/a7f3-full.jpg
landscape/a7f3-thumb.jpg
manifest.json

{
  "categories": [
    { "id": "landscape", "title": "Landscape" },
    { "id": "portrait",  "title": "Portrait" }
  ],
  "images": {
    "landscape": [ { "id": "a7f3", "title": "Fog over the lake" } ],
    "portrait":  []
  }
}
D-006

Image processing in the browser

Accepted2026-10-19
Decision
The admin page resizes each image in the browser before upload. It creates a large version (about 2400 px wide) and a thumbnail (about 600 px wide).
Why
Cloudflare's image resizing is not part of the free plan. Resizing in the browser needs no server-side processing.
D-007

CMS security: HTTP Basic Authentication

Accepted2026-10-19
Decision
A middleware function protects /admin and /api/admin/* with HTTP Basic Authentication. The password is stored as the Cloudflare secret ADMIN_PASSWORD, never in the code.
Why
It takes about 10 minutes to build and needs no login page.
Limits
There is no protection against password guessing, so the password must be long. There is no real logout.
Later
We can switch to Cloudflare Access (email one-time code login, free up to 50 users) without changing the site.
D-008

Ordering UI: up/down buttons first

Accepted2026-10-19
Decision
The first admin version uses "up" and "down" buttons to reorder images. Drag and drop may follow later.
Why
It is faster to build and fits the time budget.
D-009

Deployment with Wrangler

Accepted2026-10-19
Decision
We create Cloudflare resources and deploy with the wrangler command-line tool.
